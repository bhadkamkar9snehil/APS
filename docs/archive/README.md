# APS Archived Documentation

Everything under `docs/archive/` is **superseded historical material** retained for traceability.

Archived documents must not be used as current product/domain/backend requirements. They may describe old workbook-era APIs, UI layouts, implementation phases, fix plans, audits or optimization passes that were valid only for earlier versions of the prototype.

Current authority is indexed at [`../current/README.md`](../current/README.md).

## Archive categories

- `legacy-analysis/` — audits and analyses of earlier Python/workbook behavior;
- `legacy-api/` — superseded API consolidation/comparison work;
- `legacy-design/` — superseded design and scheduling analysis documents;
- `legacy-implementation/` — old phase completion/progress/refactoring reports;
- `legacy-optimization/` — old optimization/fix completion summaries;
- `ui/` — superseded UI/visibility/API mapping documents;
- `fix-plans/` — historical fix plans;
- `misc/` — orphaned or low-authority historical notes.

The files remain available so implementation history and parity evidence are not lost, but their path is intentionally explicit: **archive means non-authoritative**.
